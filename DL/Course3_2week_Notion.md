
  
2주차는 모델의 성능을 향상시키기 위한 **오차 분석(Error Analysis)**, **Train/Dev/Test 데이터 불일치(Data Mismatch) 해결법**, 그리고 **인간 수준의 성능(Human-level Performance)을 활용한 편향/분산 분석** 및 **전이 학습/다중 작업 학습**을 다룹니다.

## 1. 오차 분석 (Error Analysis)

모델의 성능이 만족스럽지 않을 때, 수동으로 오차 원인을 분류하면 어떤 문제부터 해결해야 할지 명확한 우선순위를 정할 수 있습니다.


### 1).오차 분석 표 작성 (Error Analysis Spreadsheet)

Dev 세트에서 잘못 분류된 예시(예: 100개)를 직접 눈으로 확인하면서 원인별로 백분율을 집계합니다.

|**이미지 번호**|**개(Dog)**|**고양이과 동물(Cat-like)**|**blurry(흐림)**|**Instagram 필터**|**비고**|
|---|---|---|---|---|---|
|1|$\checkmark$|||$\checkmark$|개를 고양이로 착각|
|2||$\checkmark$|||여우/사막여우|
|3|||$\checkmark$||화질 저하|
|**비율(%)**|**8%**|**43%**|**61%**|**9%**||

- **우선순위 판단:** '개' 문제(8%)를 해결하기 위해 몇 주를 쏟아붓는 것보다, '흐린 이미지(blurry)'(61%)나 '고양이과 동물'(43%) 문제를 개선하는 것이 전체 성능 향상의 천장(Ceiling)을 훨씬 높여줍니다.
    
      
### 2). 잘못 레이블링된 데이터 처리 (Incorrectly Labeled Data)

- **Train 세트:** DL 알고리즘은 무작위 오차(Random Error)에 꽤 강하므로, Train 세트의 라벨 오류 비율이 낮다면 굳이 수정하지 않아도 됩니다. (단, 체계적 오차(Systematic Error)에는 취약)
    
- **Dev/Test 세트:** 오차 분석 시 "잘못된 라벨로 인한 오차 비율"을 확인합니다. 전체 오차에서 라벨 오류가 차지하는 비중이 크다면 Dev/Test 세트의 라벨을 수정해야 합니다.
    
    - **지침:** Dev와 Test 세트는 동일한 분포를 유지해야 하므로, Dev 세트 라벨을 수정했다면 Test 세트 라벨도 동일하게 수정합니다.
        
          
## 2. 데이터 불일치 (Data Mismatch) 문제 해결

실제 머신러닝 프로젝트에서는 웹에서 수집한 고화질 데이터(Train)와 사용자가 앱으로 찍은 저화질 데이터(Dev/Test)의 분포가 다를 때가 많습니다.


### 1).데이터 합치기 및 분할 전략

웹 데이터 200,000개와 앱 데이터 10,000개가 있을 때:


- **잘못된 방법:** 210,000개를 섞어서 Train/Dev/Test로 나누기 $\rightarrow$ Dev/Test 세트가 웹 데이터로 채워져 실제 앱 환경 평가가 안 됨.
    
- **올바른 방법:** 앱 데이터 일부(5,000개)를 Dev(2,500개)와 Test(2,500개) 세트로 배정하고, 나머지 앱 데이터(5,000개)와 웹 데이터 전체를 **Train 세트**에 넣음.
    
### 2).Train-Dev 세트 도입 (편향/분산 및 데이터 불일치 진단)

Train 세트와 Dev 세트의 분포가 다를 때는 기존의 Train 오차와 Dev 오차 비교만으로는 데이터 불일치 문제인지, Overfitting(분산) 문제인지 구별할 수 없습니다. 따라서 **Train-Dev 세트**를 추가합니다.

> **Train-Dev 세트:** Train 세트와 동일한 분포에서 추출하지만, 모델 학습에는 사용하지 않는 검증용 데이터
> 
>   

```
[ Train 세트 (웹+일부 앱) ] ───(학습)───> 모델
          │
          ├──> [ Train-Dev 세트 (웹+일부 앱) ] ── (오차 측정)
          │
[ Dev / Test 세트 (앱 전용) ] ────────────── (오차 측정)
```

### 3).오차 유형 진단 기준

1. **Avoidable Bias (회피 가능한 편향):** Human Error $\leftrightarrow$ Train Error 격차
    
2. **Variance (분산):** Train Error $\leftrightarrow$ Train-Dev Error 격차

3. **Data Mismatch (데이터 불일치):** Train-Dev Error $\leftrightarrow$ Dev Error 격차

4. **Degree of Overfitting to Dev Set (Dev 세트 과적합):** Dev Error $\leftrightarrow$ Test Error 격차

- **예시 상황:**
    - Human Error: 0% / Train Error: 1% / Train-Dev Error: 1.5% / Dev Error: 10%

    - $\rightarrow$ Train-Dev와 Dev 간 오차가 커졌으므로 **Data Mismatch가 주원인**입니다.

### 4).데이터 불일치 해결 전략

1. Train 세트와 Dev 세트의 차이점(음성 노이즈, 화질 등)을 수동 오차 분석으로 파악합니다.

2. Train 세트를 Dev 세트 데이터와 유사하게 만듭니다.
    
    - **인공 데이터 합성 (Artificial Data Synthesis):** 깨끗한 음성에 자동차 소음 데이터를 합성하거나, 이미지에 필터를 씌우는 방식.

    - _주의:_ 자동차 소음을 1초짜리 단일 음원으로 돌려 쓰면 소음 데이터에 과적합될 위험이 있습니다.

## 3. 인간 수준의 성능 (Human-level Performance)

머신러닝은 인간 수준의 성능을 넘어서기 전까지 빠르게 발전하지만, 그 이상에 도달하면 성장 속도가 완만해지는 **베이즈 오차(Bayes Error, 이론상 최소 오차)** 한계에 도달합니다.

### 1).Avoidable Bias를 구하기 위한 인간 수준의 성능 정의

상황에 따라 '인간 수준의 성능'의 정의가 달라집니다. (예: 의학 이미지 분류)

- 일반인의 오차: 3%
- 일반 의사의 오차: 1%
- 전문의 팀의 오차: 0.5%

모델의 Train 오차가 0.7%일 때, 베이즈 오차의 대리 지표(Proxy)로 가장 우수한 성적(전문의 팀의 0.5%)을 선택해야 Avoidable Bias가 0.2%임을 파악하고 최적화 방향을 잡을 수 있습니다.

## 4. 전이 학습과 다중 작업 학습 (Transfer & Multi-task Learning)

### 1).전이 학습 (Transfer Learning)

태스크 A(예: 이미지 인식)에서 학습한 지식을 태스크 B(예: X-ray 의료 진단)에 재사용하는 기법입니다.

- **수행 방법:**

    1. 기존 모델의 마지막 출력 레이어(및 가중치)를 제거합니다.
    2. 새로운 태스크 B의 레이어를 부착하고 임의의 가중치로 초기화합니다.
    3. 데이터 양에 따라 마지막 레이어만 재학습(Fine-tuning)하거나 전체 네트워크를 재학습합니다.

- **전이 학습이 유용한 조건:**

    - 태스크 A와 B가 동일한 입력 형태(예: 이미지, 음성)를 가질 때
    - 태스크 A의 데이터 양이 태스크 B의 데이터 양보다 **훨씬 많을 때**
    - 태스크 A의 하위 개념(Low-level feature) 학습 결과가 태스크 B에 도움이 될 때

### 2).다중 작업 학습 (Multi-task Learning)

하나의 신경망이 동시에 여러 개의 작업을 수행하도록 학습시키는 방식입니다. (예: 자율주행 - 보행자, 차량, 표지판, 도로 경계선 동시 인식)

- **손실 함수 예시:**
    $$\mathcal{L}(\hat{y}, y) = \frac{1}{m} \sum_{i=1}^{m} \sum_{j=1}^{4} L(\hat{y}_j^{(i)}, y_j^{(i)})$$
    
    _(일부 라벨 $y_j$가 유실(Unlabeled)되어도 학습 가능)_

- **다중 작업 학습이 유용한 조건:**
    - 유사한 하위 특성을 공유하는 태스크 모음일 때
    - 각 태스크별 데이터 양이 비슷할 때
    - 충분히 큰 신경망을 사용할 때 (작은 네트워크는 다중 작업 시 성능 저하)

## 5. 종단간 딥러닝 (End-to-End Deep Learning)

전통적인 머신러닝 pipeline(파이프라인)의 여러 단계를 하나의 대형 신경망으로 대체하는 접근법입니다.

- **예시 (음성 인식):**
 
    - 전통적 방식: 음성 $\rightarrow$ 특징 추출(MFCC) $\rightarrow$ 음소 인식 $\rightarrow$ 단어 구성 $\rightarrow$ 텍스트
    - End-to-End 방식: 음성 $\rightarrow$ [대형 신경망] $\rightarrow$ 텍스트

- **장점:**

    - 데이터 스스로 가중치를 학습하므로 인간의 선입견/제약(Hand-designed features)을 배제할 수 있음.
    - Intermediate 단계 구축 비용 감소.

- **단점:**
    - **엄청난 양의 데이터가 필요함.**
    - 수작업으로 직접 설계된 유용한 컴포넌트(Hand-designed Prior)를 활용하지 못함.

- **적용 판단:**

    - 데이터가 충분하다면 End-to-End가 강력하지만, 데이터가 부족하거나 복잡한 문제는 **다단계(Multi-step) 방식**이 더 뛰어난 성능을 발휘합니다.

    - _(예: 얼굴 인식 문 열기 시스템은 [사진 $\rightarrow$ 얼굴 잘라내기] + [잘라낸 얼굴 $\rightarrow$ 신원 확인] 2단계 구조가 단일 End-to-End보다 성능이 훨씬 높음)_
